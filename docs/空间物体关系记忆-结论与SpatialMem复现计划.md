## 1. 问题重述

最初的问题是"第一视角设备如何通过视频流重建室内空间并记忆物品位置"。经讨论后收窄：

**真正需要的是"物体 + 属性 + 物体间关系"的可查询记忆，而不是像素级场景重建。**

典型需求示例："被子在客厅中央的桌子上"——需要：

1. 识别物体（被子、桌子、客厅）；
2. 识别物体所在位置（桌子在客厅中央）；
3. 记录物体之间的关联（被子在桌子上、桌子在客厅里）。

## 2. 核心结论

### 结论 1：需要"轻量几何"，不需要"场景重建"

| 层次 | 内容 | 对物品关系记忆是否必需 |
|---|---|---|
| 稠密场景重建 | 网格 / 3DGS 点云、光照、像素细节 | 不需要，纯算力与存储浪费 |
| 轻量几何 | 相机位姿 + 相对深度 + 全局竖直对齐 + 物体 3D 框/质心 | 很需要，保证跨视角一致性与"距离/方向"可度量 |
| 语义层 | 检测、VLM 嵌入、关系谓词、层级记忆 | 核心，即"物体+属性+关系" |

依据：SpatialMem 明确以"度量 3D 作为可解释的索引支架，而非显式建图目标"为设计原则，位姿/深度后端可插拔（VGGT / SLAM3R / COLMAP），不需要专用深度传感器。

### 结论 2：关系表示由关系类型决定——全局度量 vs 视角标签

| 维度 | 全局度量（allocentric） | 视角标签（egocentric） |
|---|---|---|
| 参考系 | 房间固定坐标系（地板平面 + 朝上 z 轴） | 用户当前头/身体朝向 |
| 稳定性 | 转头、走动都不变 | 转个身就变 |
| 能回答 | "被子在桌子中央""离窗户 2 米" | "在你左前方" |
| 代价 | 需要位姿+尺度对齐，误差会累积 | 轻量，单帧即可 |
| 适用关系 | 支撑/包含/邻近/上下等物理关系 | 左/右/前/后等指示关系 |

**二者互补而非二选一**：物理关系放全局坐标系判定（SpatialMem 的 `on` 定义为"物体底面与支撑面顶面平齐 + 投影重叠"，用 z 轴高度差判定）；指示关系按帧打标签、跨视角融合。回答用户时：先查全局层得到稳定事实，再按用户当前位姿做坐标变换输出行动指令（"在你左前方约两米"）。

### 结论 3：身份保持先于关系——发现与跟踪是最大瓶颈

- OVQ2D/ESOM（WACV 2026）消融：端到端在线成功率仅 ~4%；"发现+跟踪"补齐后达 81.9%。
- REMIND（2026）：无需位姿/深度的长期多物体再识别，IDF1 达 90.35%。
- 工程含义：先解决"同一物体跨帧认得出、跟得住"，再谈关系推理。

### 结论 4：更新策略——区分"用户移动"与"物体移动"，事件驱动而非每帧重写

- 用户走路/转头 → **不更新关系图**，只更新用户位姿（VIO），回答时做视角变换。
- 用户移动物体 → **更新关系图**，但需"离开旧支撑 + 被新支撑承接"双条件 + 多帧确认，避免遮挡/晃动误判；旧关系带时间戳保留（"被子之前放在沙发上"也可能是有效答案）。
- 实时性分层：
  - 帧级实时：位姿、检测、跟踪（端侧低功耗）；
  - 事件级异步：VLM 关系推理、记忆提交（多帧证据确认后，或场景切换/静置时批量刷新）。
- 建议显式存储用户自身轨迹（"最后一次经过桌子是 10:20"），对找东西与回忆都有价值。

### 结论 5：门/窗识别服务于"锚定"，不是检索目标本身（SpatialMem 原文核验）

SpatialMem 中识别门/窗的目的**不是"找到门"**，而是与墙一起构成记忆树的
**L1 结构性锚点层**，作为全部空间推理的稳定度量参照，具体四类用途：

1. **度量接地（metric grounding）**：把"门旁边""窗户左边 2 米"这类自然语言空间表达
   锚定到统一直立度量坐标系，转成可计算的距离/方向/可见性关系（§3.4）；
2. **物体的稳定上下文**：物体（L2）是动态的，门/窗/墙是静态的，物体节点挂在锚点上，
   物体移动后仍可重新定位，对应"墙定义房间、房间包含物体"的层级；
3. **多跳关系查询与导航航点**：关系查询沿图行走（论文示例 wall → window → mug），
   导航指令被翻译为"锚点 + 物体"航点序列，"去门口/从门出去"以门为关键航点（§3.6）；
4. **跨视角融合自我中心关系**：左/右/前/后等视角相关标签先按帧记录，
   再用锚点做跨视角对齐与消歧（§3.4）。

检测与晋升方式（§3.2）：墙 = 大竖直平面；门/窗 = 竖直开口
（从边缘/深度间隙提取），经**多视角验证、合并去重、时序持续**筛选后
升为 L1 节点，携带几何参数（平面/框）、语义类型与置信度，并预留物体挂载边。
原文评测（Scene 1）中门/窗锚点关系得分均为 0.82（墙 0.88），
即门/窗是作为"锚点关系"被评估，而非独立的目标检测任务。

## 3. 推荐记忆架构（SpatialMem 式）

```
房间(客厅)                                    ← 根：场景元数据/全局坐标系
 └─ 结构性锚点: 墙/门/窗(桌子的参照)            ← L1：几何(平面/框)+语义+置信度
     └─ 家具/物体: 桌子 {3D框, 类别, 嵌入, 证据裁剪图, 最后观察时间}
         ├─ 物体: 被子 {类别,颜色,尺寸,视觉嵌入,3D质心,最后观察时间,状态}
         └─ 关系边: on(被子,桌子,置信度0.9,时间戳) | near(桌子,窗)

每节点存：几何 G(v)、语义 S(v)、文本描述 D(v)
每节点带双层描述：
  Layer 1（图像级）：随当前帧变化，记录瞬时视图
  Layer 2（场景级）：多视角一致后才写入，保守更新防漂移
查询 = 沿图行走 + 谓词校验（距离/方向/可见性）
```

## 4. SpatialMem 复现计划

### 4.1 论文管线（按论文提取）

```
RGB 视频(egocentric)
  → 位姿 + 深度（可插拔后端：VGGT/SLAM3R/COLMAP）
  → 点云融合 → 竖直度量坐标系（地板平面拟合 + 朝向稳定 + 高度先验定尺度）
  → 结构性锚点：墙=大竖直平面；门/窗=竖直开口（多视角验证后提升为 L1 节点）
  → 物体节点：2D 检测/分割 → 提升到 3D 框（可选 SpatialLM 粗框先验，多视角精化）
  → 双层描述（属性 + 相对锚点/物体关系）
  → 有根树记忆（Root=房间, L1=锚点, L2=物体, L3=描述）
  → 查询：locate / relational query / 导航路径
```

### 4.6 无感持续学习设计原则（M5，2026-08-12）

**目标**：用户零操作、后台不停地把"看到过的物体"沉淀为可检索记忆；
"扫一眼认不出来"是常态，记忆的价值在于把一次次的自然交互结果积累下来，
下次直接检索（对应 SpatialMem/ESOM 的 episodic object memory，计划 §2 结论 3：
身份保持先于关系）。

**核心原则：只积累证据，不急于下结论；结论靠多源一致，升级靠自然时机。**

| 机制 | 行为 | 用户负担 |
|---|---|---|
| 后台候选池 | 每秒/每帧做 novelty 检测：新实例（与已知节点嵌入距离 > 阈值）建低置信度候选，含裁剪图/3D 锚点/出现时段 | 零 |
| 机会式确认 | 用户提问/模型提到物体/OCR 读到印刷字/多帧一致 → 候选升级为确认节点，不弹窗不询问 | 自然发生 |
| 身份保持 | 同一物体跨帧、跨会话（放回再拿出）靠视觉嵌入/再识别认出来 | 零 |
| 检索优先问答 | 问"口红在哪"→ 先查记忆命中再答，附"根据记忆…"，不确认才扫当前画面 | 零 |
| 遗忘与纠正 | 旧/移动物体带时间戳归档（现有 archive 机制）；用户说"不对"即降级 | 一句话 |

**写入的数据模型（确认节点）**：`{标签, 颜色, 尺寸, 裁剪图/视觉嵌入, 3D 锚点,
来源(interactive|passive|ocr), 置信度分级, 首次/最近出现时间}`。

**关键难点与对策**：
1. 指代关联（用户问的到底是哪个物体）：说话附帧（客户端 attachBrainFrame 已有）
   + 画面焦点 + 文本线索；拿不准只记文本不记位置；
2. 记忆污染（模型答错就记错）：置信度分级——OCR 印刷字 > 视觉外观 > 猜测；
   低置信只进候选；保留纠正通道；
3. 触发策略：novelty 检测避免每帧重复建节点；
4. 隐私/功耗：全端侧、加密落盘、后台低频采样。

**M5 拆解**：
- M5.1 候选池 + novelty 检测（跨帧同实例合并）；
- M5.2 机会式确认（交互答案绑定候选 + OCR/多帧一致升级）；
- M5.3 检索优先问答（记忆命中先答，画面确认兜底）；
- M5.4 视觉再识别 + 遗忘/纠正（跨会话身份、时间戳归档）。

**验收**：新场景 M4 基线（待人工核对 GT）→ 注入"交互确认一条口红"→
模拟用户次日询问，验证命中率与"无感"（无任何用户记忆操作）。

### 4.7 场景隔离落地（2026-08-29）

居家是长期场景（需长期记忆），教室等临时场景下次不一定再来——两者不能互相污染。
客户端已实现「场景内强隔离 + 跨场景显式复用」：

1. **场景字段与持久化**：`ConfirmedNode` 增加 `sceneId/sceneName`；
   旧版无场景数据归入 `legacy` 场景，与新场景隔离；
2. **SceneRegistry（`SceneRegistry.kt`）**：门/窗/墙锚点指纹
   （type:direction:2m 距离桶）识别场景，回访时靠指纹找回旧记忆；
   `家` 自动置顶（长期保留），临时场景 7 天未回访自动归档（不参与默认检索，
   显式查询仍可命中）；
3. **场景切换共识**：连续 2 次观察指向同一新场景才切换，防门口晃动误切；
   无匹配但有明确场景证据（位置场景词或 ≥2 锚点）才新建场景；
4. **去重按场景收敛**：`upsertConfirmed`/`dedupConfirmed` 只在同一场景内合并——
   教室的「门」绝不会与家里的「门」合并；
5. **检索分场景**：默认只答当前场景；「家里的门」「教室的窗户」等限定词
   显式跨场景查询（`extractSceneMention`）；记忆快照只注入当前场景。

**P0-2 回访恢复 + 语音置顶（2026-08-29）**：

- **回访恢复**：`SceneRegistry.lookup` 活跃场景优先；归档场景凭
  **强指纹匹配（Jaccard ≥ 0.7，普通匹配阈值 0.5）或唯一名称**命中并标记
  `revived=true`，经场景切换共识（连续 2 次观察）后 `activateScene` 找回旧记忆
  （旧节点仍按原 sceneId 存储，恢复后立即可检索/导航）；
- **语音置顶**：「把这里记为家/设为家/记住这是家/置顶这个场景」→ 新增
  `PIN_SCENE` 命令 → `pinCurrentScene()`：当前场景 `pinned=true` 并重命名为
  「家」（7 天不归档），同步更新该场景已入库节点的 `sceneName`，保证
  「家里的门」等跨场景查询命中；无当前场景时播报引导文案。

### 4.8 导航路径/航点（2026-08-29）

SpatialMem §3.6 的 navigation waypoint 已在客户端落地（`MemoryNavigator.kt`）：

- 「带我去门口」「去厨房」「走到窗户那」→ 解析为目标词（去前缀/后缀/别名，
  `门口`→`门`），在（当前或指定）场景记忆中匹配锚点/物体；
- 航点序列：目标是锚点 → 单航点；物体挂了 `nearAnchor` → 先到锚点再到物体；
  只有支撑物 → 先到支撑物（桌子等）再到物体；
- 每步带方向（偏左/偏右/正前方/后方）与粗略距离（视角锚点或 VLM 估距）；
- 语音分步播报：完整路径一次播报，说「继续/下一步」逐段推进；
  无进行中的导航时「继续」按暂停恢复处理，不误报；
- 命令路由新增 `NAVIGATE`（「去/到」低权重，不与「出门模式/物品在哪」抢）。

局限：当前航点方向/距离来自记忆时的视角与 VLM 估距，不是实时位姿——
真正「跟随导航」需 P0 的位姿/IMU 采集闭环（§4.2 差距行）。

### 4.8.1 锚点多视角确认（P0-3，2026-08-29）

连续观察管线（`hint=continuous`，5s/次且画面灰度指纹变化≥阈值才触发，
因此每次观察天然来自不同视角）中，锚点不再单帧入库，由
`AnchorMultiViewConfirmer.kt` 做多视角确认：

- **签名 = type:direction**，距离用 **2m 容差**匹配（避免 2m 距离桶边界抖动，
  如 5.8m/6.1m 视为同一扇门）；同类型同方向但距离突变（另一扇门）重新投票；
- **连续语义**：本帧出现的锚点计数 +1，未出现的衰减 -1、归零移除——
  断帧/换方向都会推迟确认；计数 ≥ 2 帧即入库（仅返回一次，之后只刷新不重复建节点）；
- **作用域**：只作用于连续观察模式；主动询问（query:/文本触发）仍即时入库；
  场景解析继续使用本帧全量锚点（待确认锚点不丢场景指纹证据），
  切换场景（`activateScene`）或关闭记忆（`enabled=false`）时清空投票。

### 4.8.2 眼镜 POSE 通道供数（位姿闭环第 1 档，2026-08-29）

经 `PosePayloadCodec` 打包。本次补齐**手机端消费链路**：

- `GlassLinkServer` 分发 `LinkChannel.POSE` → `X3ProVideoSource.onPosePacket`
  解码采样批：时间戳经 `ClockSyncEstimator` 换算到手机时钟域（未收敛用到达
  时间下界，与视频帧同口径），四元数经 `PoseOrientation`（与
  `SensorManager.getRotationMatrixFromVector+getOrientation` 同口径的纯数学
  转换）换算 azimuth/pitch/roll；
- `CaptureCoordinator.onGlassesPose` 喂给视觉位姿管线并落盘 pose.csv；收到
  首包即锁定眼镜位姿源——手机传感器不再喂视觉/落盘，保证 pose.csv 与眼镜
  视频帧同源（供 COLMAP/位姿对齐）；切回手机模式或停止时复位。

### 4.8.3 跟随视角 + 实时相对转向（位姿闭环第 2 档第 1 阶段，2026-08-29）

把眼镜实时朝向接入地图导航，替换"记忆时视角"的静态方位：

- **朝向链路**：`CaptureCoordinator` 位姿回调 → `MemoryLearningCoordinator
  .updateUserPose`（EMA 平滑 + 6Hz 节流）→ `NavPoseState(mapFacingRad)`
  → `NavigationOverlayView`；
- **小地图跟随视角**：叠加层以用户位置为旋转中心把地图旋转到 heading-up，
  并绘制用户箭头（位置暂用地图起点）；
- **相对转向播报**：`planWithMap` 首段与「继续/下一步」剩余分段都用实时朝向
  计算转向（直行/左转约X度/右转约X度/调头），阈值为 15°/45°/150°；
- **坐标系约定**：发起导航时用户面向地图 +y（`mapFacing = π/2 + startHeading
  - heading`），左转（方位角减小）等价地图朝向逆时针；地图与真实朝向的
  恒定偏移由该锚定约定吸收，纯数学可单测。

剩余：位置递推（步数检测/IMU 积分，需眼镜侧补加速计通道）与自动到达判定。
